# S3 / R2 双向同步与备份

racomi 默认读写本地资料，关闭同步时无需账号或网络服务。配置自己的 S3 兼容存储后，可在多台设备间双向同步，并保留加密的远端历史版本。Cloudflare R2 可直接作为 S3 后端使用，无需部署 Worker 或独立服务端。

应用内可在 **指南 → 同步与备份** 离线查看配置说明，或从 **设置 → 备份与迁移 → S3 / R2 同步 → 配置指南** 直接打开。

## 同步范围

| 同步到其他设备 | 只保留在本机 |
| --- | --- |
| Git 来源、分支、扫描范围、订阅方式和可移植清单 | 本地仓库路径、刷新错误、缓存 |
| 技能记录和实际技能文件，包括本地导入的技能 | 技能的本地来源路径 |
| 预设名称、说明、图标及技能成员 | 项目根目录、项目和全局的技能选择及部署记录 |
| 主题、语言、导航布局、复制／软链接偏好、内置目录默认选择、相对项目目录模板 | 自定义绝对路径、本机目录的默认选择、侧边栏宽度和分栏宽度 |
| 云端已提交版本的历史 | S3 凭据、Session Token 和加密口令 |

同步更新本地技能资料后，已有项目和全局配置会按照内容变化显示待应用。请继续 **预览变化 → 手动应用**，同步不会直接修改 Agent 部署目录。来自本地路径的技能仍可同步，其来源路径会从共享记录中移除。

## Cloudflare R2

设置同步时可以选择 **Cloudflare R2** 或 **手动 S3**。两种方式分别保留设置，只有点击 **保存同步设置** 后才切换当前同步方式；切换选项或取消弹窗不会改变后台同步目标。

### 通过 Cloudflare 授权

1. 选择 **Cloudflare R2 → 连接 Cloudflare**，在系统浏览器中登录并授权访问指定账号。
2. 返回 racomi，选择账号、存储桶的司法辖区及私有存储桶，再选择使用该桶。应用自动生成该桶范围的对象读写凭据，填写端点与区域。
3. 填写对象前缀与加密口令，测试连接后保存。所有设备继续使用相同的端点、桶、前缀和加密口令。

OAuth 负责授权与凭据配置；同步仍使用同一个 S3 协议和加密引擎，同步范围、冲突、条件写入和历史恢复与手动配置一致。仍需先在 Cloudflare 开通 R2；账号成员须有创建 Account API Token 的权限。

OAuth 令牌与自动创建的 S3 凭据仅存于本机系统凭据存储（macOS Keychain / Windows Credential Manager / Linux Secret Service，如 GNOME Keyring 或 KWallet；Linux 未运行 Secret Service 时无法使用 Cloudflare 授权连接，手动 S3 不受影响），不返回前端或进入备份。同步加密口令继续按现有方式保存在本机 `0600` 配置文件。OAuth 不要求离线访问：有效的 S3 凭据可继续同步；授权过期后，选择桶、续期凭据或断开连接时需重新授权。**断开 Cloudflare** 会删除应用生成的远端凭据并撤销授权，保留手动 S3 设置。

若构建尚未配置发行者的 OAuth Client ID，连接入口会说明不可用，仍可使用手动配置。发行者在 `internal/desktop/cloudflare-registration.json` 中填写公开 Client ID 后重新构建；普通用户无需填写。注册参数及真实 PoC 验证见 [OAuth 接入与验证](r2-oauth-poc.md)。

### 手动 S3 配置

1. 在 Cloudflare 控制台的 R2 中创建私有存储桶，例如 `racomi-sync`。
2. 在 R2 的 **Manage API tokens** 中创建账号或用户令牌，权限选 **Object Read & Write**，范围限定为刚创建的桶。记录页面提供的 **Access Key ID** 和 **Secret Access Key**；应用需要这两个 S3 凭据，不填写 Cloudflare API Token 原文。
3. 在 racomi 打开 **设置 → 备份与迁移 → S3 / R2 同步 → 设置同步**：

| 字段 | R2 配置 |
| --- | --- |
| S3 端点 | `https://<ACCOUNT_ID>.r2.cloudflarestorage.com` |
| 存储桶 | `racomi-sync`，不附加到端点 URL |
| 区域 | `auto` |
| 对象前缀 | 默认 `racomi`，也可使用 `personal/skills` 等独立前缀 |
| Access Key ID / Secret Access Key | 第 2 步生成的 S3 凭据 |
| Session Token | 普通长期凭据留空；临时凭据按提供方要求填写 |
| 使用路径式寻址 | 开启 |
| 加密口令 | 至少 12 个字符，所有设备使用同一个口令 |
| 自动同步 | 可选，默认关闭；开启后仅在应用打开时按间隔运行 |

4. 点击 **测试连接**，成功后 **保存同步设置 → 立即同步**。
5. 在其他设备填写**相同的端点、存储桶、前缀和加密口令**，再执行立即同步。设备可使用不同的桶范围访问密钥。

`ACCOUNT_ID` 是 Cloudflare 账号 ID，不是邮箱、域名或令牌 ID。有司法辖区限制的桶须使用控制台显示的对应端点，例如 EU 的 `https://<ACCOUNT_ID>.eu.r2.cloudflarestorage.com`。所有设备须使用同一端点域名；端点也参与加密空间身份。

存储桶保持私有，无需启用 `r2.dev` 公共访问、自定义域名、浏览器 CORS 或 Worker。请求由桌面应用的本机后端发出。配置依据 [R2 凭据文档](https://developers.cloudflare.com/r2/api/tokens/) 和 [S3 API 兼容文档](https://developers.cloudflare.com/r2/api/s3/api/)。

## AWS S3 与其他兼容服务

先创建私有桶和限定权限的凭据。AWS S3 的端点示例为 `https://s3.us-east-1.amazonaws.com`，区域须填写桶的实际区域，例如 `us-east-1`；使用虚拟主机式寻址时关闭“使用路径式寻址”。其他 S3 服务使用提供方的 API 端点、签名区域及寻址模式；支持本机 S3 服务的回环 HTTP 地址，远端服务必须使用 HTTPS。端点只能包含协议、主机与可选端口，不包含桶名、路径、查询参数或登录信息。

需要以下权限：

- 桶上的 `s3:ListBucket`，用于列举该前缀内的历史对象。
- 指定前缀内的 `s3:GetObject` 和 `s3:PutObject`，用于读取和提交同步数据。
- 指定前缀内的 `s3:DeleteObject`，用于连接测试后清理临时探测对象。

AWS IAM 策略示例，使用前请替换桶名和前缀：

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::racomi-sync",
      "Condition": { "StringLike": { "s3:prefix": ["racomi/*"] } }
    },
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:PutObject", "s3:DeleteObject"],
      "Resource": "arn:aws:s3:::racomi-sync/racomi/*"
    }
  ]
}
```

服务须提供正确的 ETag，并真正执行 `If-Match` / `If-None-Match` 条件写入；连接测试会检查它们，避免两台设备同时覆盖共享版本。对象存储的强一致读取和列表行为也关系到并发安全。AWS 访问方式见 [S3 官方文档](https://docs.aws.amazon.com/AmazonS3/latest/userguide/access-bucket-intro.html)。

## 双向合并与删除

首次连接会合并已有本地资料与云端资料，不要求先清空新设备。之后根据上次共同版本进行三方合并：

- 不同记录的修改自动合并，例如一台设备新增来源，另一台编辑不同的预设。
- 同一记录双方产生不同修改，或一方删除、另一方修改时，进入冲突处理，逐条选择保留本地或云端版本。
- 已同步记录的删除会传播。离线设备再次连接时不会仅凭旧副本把已删除资料重新带回来。
- “来源仓库移除了技能”仍遵守原有规则，标记状态并保留本地技能；它与在 racomi 中删除技能是不同操作。
- 冲突处理期间其他设备继续修改资料时，需要重新同步并处理最新版本，旧选择不会静默覆盖新变化。

云端变化完整下载、解密和校验后才提交本地状态。网络断开时继续使用本地资料，连接恢复后重试；开启自动同步后，应用打开期间按设置间隔尝试。间隔范围为 1–1440 分钟。使用不同前缀可以隔离个人、工作等资料库。

## 备份历史与恢复

每次有变化的成功同步保存不可变历史版本和技能内容对象；未变化的技能内容复用。**设置 → 备份与迁移 → S3 / R2 同步 → 云端备份** 显示最近 100 个已提交版本及技能、预设数量。选择恢复时会明确展示版本时间和数量；恢复前创建本地快照，再将所选资料作为一个新同步版本发布，其他设备下次同步时获得恢复结果。

历史与对象暂不自动清理，也不设置保留期限。请留意桶容量，不要配置会自动删除有效同步对象的生命周期规则。云端历史不是 ZIP 文件，单独下载某个对象不能替代完整恢复；已有本地快照及 ZIP 导入导出仍可独立使用。

传输限制为单个技能压缩包最大 64 MiB、解压后最大 128 MiB／10,000 个文件条目；同步清单最大 32 MiB。超限、损坏或含不安全路径的内容会停止同步并保留本地可用资料。

## 加密与凭据

共享清单、技能内容和历史在客户端进行 AES-256-GCM 加密；口令通过 PBKDF2-SHA256（210,000 次迭代）派生密钥。密钥身份与端点、桶及前缀绑定，因此这些配置和口令须在各设备一致。对象服务仍能看到对象键、大小、请求和时间等存储元数据。

手动 S3 凭据和同步口令存于本机数据目录中的 `cloud-sync-config.json`，以 `0600` 文件权限限制访问；Cloudflare OAuth 令牌和自动生成的 S3 凭据单独存入系统凭据存储。它们不进入共享资料或 ZIP 备份。设置界面只显示是否已保存，不回显敏感值；留空保留原值，更换端点或 Access Key ID 时须重新填写 Secret Access Key。已保存的 Session Token 可勾选“清除已保存的 Session Token”后保存来移除；勾选时测试连接也不使用该 Token，但测试不会修改已保存的配置。普通 R2 长期凭据不需要 Session Token，请勿在该字段填写 Cloudflare API Token。临时凭据过期后需手动更新。

请在可靠位置额外保存加密口令。丢失所有设备上的口令后，存储提供方也无法恢复密文。需要更换口令时，先用现有设备确认本地资料完整，再使用新的前缀和口令建立新的同步空间，逐台更新配置；不要直接在现有空间更换口令。

## 常见连接问题

| 提示或现象 | 检查 |
| --- | --- |
| AccessDenied / HTTP 403 | 桶名、前缀限制、对象读写／删除及列表权限；R2 须使用桶范围的 Object Read & Write。 |
| 签名或区域错误 | API 端点、实际区域、Access Key ID 与 Secret 配对、临时 Session Token，以及设备时间。R2 区域填写 `auto`。 |
| 无法解密 | 各设备的口令、端点域名、桶及前缀是否完全一致。 |
| 条件写入不受支持 | 提供方或代理未正确实现 ETag / If-Match / If-None-Match；需要换用支持这些功能的 S3 服务。 |
| 同步完成后 Agent 未看到变化 | 同步只更新本地资料，请在项目／全局页面预览并手动应用。 |
| 修改配置后看不到旧历史 | 历史属于原来的端点、桶、前缀和口令空间；切回原配置查看。 |
